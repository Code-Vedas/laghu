# ngx-laghu RUM, Redis, and Instrumentation

## Instrumentation Is Not Injected

Confirm the feature is enabled in the effective location and the response is a complete eligible HTML document.
Hash-only, nonce-only, or `strict-dynamic` CSP that cannot authorize the fixed same-origin script correctly preserves the original page.
Inspect the served CSP and instrumentation markup instead of weakening CSP without review.

## Reports Are Rejected

Check same-origin method, MIME type, request bounds, template/catalog freshness, viewport bucket, sample rate, and rate limiting.
Unknown opaque keys and expired templates are rejected deliberately and will relearn from a newly issued page.

## Redis/Valkey Does Not Synchronize

Verify hiredis loading, DNS, TCP reachability, certificate chain, hostname verification, credentials, database permission, Lua support, timeout, and key prefix.
`NOSCRIPT` should trigger one script reload; repeated contract or type errors require inspecting the backend keyspace and Laghu version.
Never copy the credential-bearing URI into a ticket or normal log.

## Learning Differs Across Workers

Confirm every worker uses the same provider digest, policy, parser/planner version, Redis prefix, and TTL.
Check pending-byte pressure and synchronization retries.
During an outage, temporary divergence is expected because memory remains available; convergence resumes through idempotent atomic batches after recovery.
