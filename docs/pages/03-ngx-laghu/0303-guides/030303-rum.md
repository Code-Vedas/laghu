# ngx-laghu RUM and Observability

RUM is memory-native in every NGINX worker.
Requests read current aggregate decisions without file or network I/O; background threads persist snapshots and synchronize Redis/Valkey batches.

Use `local:` for one persistent server, `memory:` for tests, and `rediss://` for a production fleet.
Redis/Valkey durability depends on its AOF, snapshot, replication, backup, and persistent-storage policy.

Monitor adapter requests, optimization decisions, original and optimized bytes, queue depth, worker heartbeat, cache size/hits, RUM pending bytes, synchronization failures, Lua contract version, template readiness, LCP/INP/CLS histograms, and purge activity.
Use the authenticated `/.laghu/metrics` and `/.laghu/ready` endpoints for fleet-facing health without exposing backend credentials or complete query strings.

Metrics use fixed process, surface, decision, failure, and worker-kind labels; paths, URLs, hosts, cache keys, credentials, headers, query strings, and process identifiers are never labels.

RUM records expire according to `rum_store_ttl` and invalidate when template structure, resource dependencies, policy, provider configuration, parser, planner, or optimizer version changes.

## LCP prioritization

With `resource_hints` enabled, Laghu prioritizes one provable same-origin image candidate by adding `fetchpriority="high"` and an exact preload. With `image_lazyload` enabled, the same candidate is excluded from Laghu-added lazy loading. Existing `fetchpriority="low"`, CSP denial, conflicting preload metadata, ambiguous responsive sources, and budget exhaustion leave the affected optimization unchanged.

Opt-in instrumentation v2 inventories at most 32 image, picture, and video-poster candidates and reports only an ordinal, kind, color-scheme bucket, and SHA-256 resource identity. Laghu accepts a report only when it matches the server-owned inventory. A learned profile requires at least three observations and 80-percent dominance in both light and dark buckets for the viewport, with the same candidate and selected resource in both themes. Version-1 reports remain valid for aggregate Core Web Vitals but do not train LCP selection.

Until a profile is ready, a bounded in-memory heuristic may select the earliest eligible body image outside `header`, `nav`, `aside`, `template`, hidden, or inert content. It excludes explicit lazy/low-priority images, tracking-sized images, data/blob and cross-origin URLs, and ambiguous pictures. No browser report contains raw URLs, selectors, text, classes, or attributes, and request processing performs no RUM-store I/O.
