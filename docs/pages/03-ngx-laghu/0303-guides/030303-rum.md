# ngx-laghu RUM and Observability

RUM is memory-native in every NGINX worker.
Requests read current aggregate decisions without file or network I/O; background threads persist snapshots and synchronize Redis/Valkey batches.

Use `local:` for one persistent server, `memory:` for tests, and `rediss://` for a production fleet.
Redis/Valkey durability depends on its AOF, snapshot, replication, backup, and persistent-storage policy.

Monitor adapter requests, optimization decisions, original and optimized bytes, queue depth, worker heartbeat, cache size/hits, RUM pending bytes, synchronization failures, Lua contract version, template readiness, LCP/INP/CLS histograms, and purge activity.
Use `laghu explain <url>` to inspect one response decision and `laghu status` for fleet-facing health without exposing backend credentials or complete query strings.

RUM records expire according to `rum_store_ttl` and invalidate when template structure, resource dependencies, policy, provider configuration, parser, planner, or optimizer version changes.
