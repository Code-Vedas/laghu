# mod-laghu RUM and Observability

Each Apache child keeps request-facing RUM state in memory and synchronizes in the background.
The Redis/Valkey Lua contract atomically validates and merges bounded idempotent batches across children and hosts.

Track request decisions, pass-through reasons, queue publication, worker heartbeat, cache hits and growth, optimized bytes, RUM pending bytes, synchronization errors, template readiness, and LCP/INP/CLS distributions.
Correlate these metrics with Apache status and error logs without emitting complete query strings, credentials, raw browser reports, or user identifiers.

Use the authenticated `/.laghu/metrics`, `/.laghu/ready`, and administration endpoints for diagnosis and controlled purge.

Metrics use fixed process, surface, decision, failure, and worker-kind labels; paths, URLs, hosts, cache keys, credentials, headers, query strings, and process identifiers are never labels.
Keep the local snapshot even with Redis so a child can restore a last-known-good view during backend maintenance.

## LCP prioritization

`resource_hints` allows Laghu to add `fetchpriority="high"` and one exact same-origin image preload; `image_lazyload` allows it to exclude that candidate from Laghu-added lazy loading. Explicit low priority, CSP denial, conflicting preload metadata, uncertain responsive selection, and exhausted request budgets skip only this optimization.

On a warm HTML response, the same filter also adds at most four deduplicated third-party `preconnect` Link headers and eight DNS-prefetch Link headers. It accepts only validated HTTP(S) origins, rejects credentialed inputs, strips resource paths, queries, and fragments, preserves application Link headers and markup, and performs no network lookup.

Instrumentation v2 records at most 32 candidate ordinals using SHA-256 resource identities and fixed viewport and color-scheme buckets. Reports must match the child's server-owned template inventory. Learning requires three observations and 80-percent dominance in both light and dark buckets for a viewport, with one candidate and resource shared by both themes. Version-1 reports continue contributing aggregate Core Web Vitals only.

Without ready evidence, a bounded memory-only heuristic considers the earliest eligible body image outside navigation, ancillary, template, hidden, or inert content. It rejects explicit lazy/low priority, tracking dimensions, data/blob and cross-origin resources, and ambiguous pictures. Raw URLs, selectors, text, classes, and attributes are never stored or exported.

## Optimization profiles

`Laghu OptimizationProfiles On` separately permits a ready profile to apply the existing safe LCP prioritization. It is off by default, so collecting RUM never changes an LCP decision merely because a profile is ready. The opaque DOM-template hash scopes every profile; a changed structure, resource dependency, policy, provider configuration, parser, planner, or optimizer version creates a different profile. A cold, expired, insufficient, or regression-suppressed profile leaves the response on the bounded heuristic path. Profile reads use the in-memory RUM view only; persistence and reconciliation remain background work.
