# Laghu Server RUM and Observability

When explicitly enabled, the server exposes bounded Prometheus metrics and aggregate health/readiness alongside cache administration and template-scoped RUM decisions.

Monitor downstream and origin latency, connection-pool saturation, queue depth, worker timeouts, cache hit ratio and growth, bytes saved, variant fanout, purge activity, RUM pending bytes, backend synchronization, template readiness, and LCP/INP/CLS histograms.
Use opaque request correlation and bounded diagnostic reason codes; never emit Redis credentials, cookies, browser identifiers, raw reports, page text, selectors, or complete query strings.

`/.laghu/metrics` exports fixed-label instance and process series for requests, decisions, cache activity and size, response bytes, failures, worker and queue state, and request latency buckets at 1, 5, 10, 25, 50, 100, 250, 500, 1000, 2500, and 5000 milliseconds plus infinity.
`/.laghu/ready` reports runtime, cache, and worker aggregation; the default degraded policy keeps serving originals when a required worker is unavailable, while strict policy returns `503`.
Both endpoints are off by default and use the configured administration CIDR and token controls.

Redis/Valkey is shared persistence, while memory remains the native read path.
During backend loss, the current process keeps its reconciled view, accumulates bounded pending deltas, publishes the local snapshot, and retries the same idempotent batch.
